# 造梦 · 故事空间：黑客松现场多人协作演示手册

> 版本：v1.0
>
> 用途：黑客松活动现场演示多人同时进入同一个在线空间、实时协同编辑，并展示不同协作者的在线状态、鼠标位置、用户名和角色颜色。
>
> 适用范围：当前 `editor/` 已接入线上域名和 Yjs 协作服务的版本。

---

## 1. 演示目标

现场需要让观众看到以下完整体验：

```text
主持人打开线上编辑器
  → 其他参与者打开同一个链接
  → 所有人进入同一个协作空间
  → 在线人数增加
  → 任意一人编辑场景
  → 其他浏览器实时看到变化
  → 其他人的鼠标、用户名和角色颜色显示在中间预览区
```

建议最终演示效果：

- 管理者：橙色鼠标；
- 编辑者：蓝色鼠标；
- 预览者：绿色鼠标；
- 用户名：每个浏览器自动生成一个 6～8 位字母数字名称；
- 鼠标离开预览区时，其他人看不到该用户的鼠标；
- 用户关闭页面后，其他人的界面自动移除该用户的鼠标和在线状态；
- 场景对象、触发器、时间线等编辑内容实时同步。

## 2. 先理解当前系统

### 2.1 现场不使用 `localhost`

当前本地开发模式是：

```text
本机浏览器
  ├─ http://127.0.0.1:5199   前端开发服务器
  └─ ws://本机:8022          本地协作 WebSocket 服务
```

这只适合开发者自己测试。

现场演示应该使用已经部署好的线上地址：

```text
https://<部署域名>/xiyou/
```

协作连接由远程服务负责：

```text
浏览器
  → HTTPS 网站
  → Cloudflare Tunnel / 反向代理
  → agentpay 的 xiyou_ws.py
  → xiyou-collab 容器
  → y-websocket
```

参与演示的人不需要：

```bash
npm install
npm run dev
```

也不需要在自己的电脑上启动协作服务器。

### 2.2 谁需要一直运行

需要保持运行的是远程服务器上的服务：

- 网站静态文件服务；
- `xiyou_ws.py` 协作网关；
- `xiyou-collab` 容器；
- Cloudflare Tunnel 或 WebSocket 反向代理；
- 如果启用了数据库或快照，还包括数据库服务。

主持人的电脑可以关闭，但远程协作服务器不能在演示期间停止。

### 2.3 当前协作方式

当前版本使用：

```text
room + key + Yjs + WebSocket
```

例如：

```text
room = hackathon-demo
key  = 现场临时令牌
```

所有参与者必须进入同一个 `room`，并使用同一个有效的 `key`，才能看到同一份实时场景。

当前项目的房间隔离示例：

```text
wukong
bajie
seng
hackathon-demo
```

不同房间互不协作。

## 4. 现场推荐方案

### 4.1 最小可用方案

黑客松现场不需要先完成正式账号体系，推荐使用：

```text
一个线上域名
一个现场专用房间
一个现场临时 key
每个浏览器自动生成随机用户名
进入时选择演示角色
Yjs 同步场景
Awareness 同步在线状态、角色、颜色和鼠标位置
```

现场访问地址示例：

```text
https://<部署域名>/xiyou/?room=hackathon-demo
```

如果使用角色参数，也可以是：

```text
管理者：
https://<部署域名>/xiyou/?room=hackathon-demo&role=manager

编辑者：
https://<部署域名>/xiyou/?room=hackathon-demo&role=editor

预览者：
https://<部署域名>/xiyou/?room=hackathon-demo&role=previewer
```

角色参数只是现场展示用途，不是正式权限控制。

### 4.2 现场角色建议

| 角色 | 鼠标颜色 | 演示职责 |
|---|---|---|
| 管理者 | 橙色 `#F97316` | 介绍项目、切换场景、展示成员状态 |
| 编辑者 | 蓝色 `#2563EB` | 添加对象、移动对象、修改触发器 |
| 预览者 | 绿色 `#16A34A` | 观察场景、移动鼠标、进入试玩模式 |

建议现场至少准备：

- 1 个管理者窗口；
- 2 个编辑者窗口；
- 1 个预览者窗口。

总人数控制在 5 人以内最稳妥，最多可以演示到 10 个连接。

## 5. 演示前一天：服务器准备

### 5.1 检查线上网站

在一台不运行本地开发服务的电脑上打开：

```text
https://<部署域名>/xiyou/
```

确认：

- 页面可以正常打开；
- CSS、JS、图片和字体没有 404；
- 编辑器界面完整显示；
- Viewport 可以加载；
- 场景底座或演示占位可以正常显示；
- 浏览器 Console 没有连续报错。

### 5.2 检查 WebSocket 协作服务

远程服务器应确认以下服务运行中：

```text
agentpay / xiyou_ws.py
xiyou-collab 容器
y-websocket-server
Cloudflare Tunnel 或反向代理
```

如果使用 Docker，检查：

```bash
docker ps
```

重点确认：

- 协作容器没有反复重启；
- WebSocket 服务监听正确端口；
- 代理转发了 WebSocket Upgrade；
- 协作服务不是只监听服务器的 `127.0.0.1`；
- 服务器磁盘空间足够；
- 容器配置了自动重启。

当前项目文档中的协作服务位置是：

```text
/www/wwwroot/xiyou-collab/
```

当前线上 WebSocket 地址是：

```text
wss://<部署域名>/xiyou-yjs
```

### 5.3 准备现场专用房间

不要使用生产项目的正式房间，单独准备：

```text
hackathon-demo
```

准备一个短期现场令牌：

```text
hackathon-demo 对应 key
```

注意：

- 不要把真实生产项目的 key 投影到大屏；
- 不要把长期 key 发到公开群；
- 活动结束后撤销或更换现场 key；
- 如果当前服务端不支持单独撤销，活动结束后至少更换该房间令牌。

### 5.4 准备演示场景

演示场景应提前准备好，不要现场从空白开始搭建。

建议至少有：

- 一个场景底座或占位空间；
- 2～4 个已有对象；
- 一个可移动的模型或图片；
- 一个带颜色/材质的对象；
- 一个触发器；
- 一条时间线；
- 1～3 个剧情节点；
- 一个可以点击“演示”或“试玩”的操作。

推荐演示场景结构：

```text
花果山觉醒
├─ 岩壁空间底座
├─ 悟空模型
├─ 结界符图片
├─ 点光源
├─ 节点 1：石卵醒来
├─ 节点 2：岩壁低语
└─ 节点 3：虚境之门
```

### 5.5 准备备份

至少准备三份：

```text
线上当前场景
主持人本地导出的 scene.json
一个可以重新加载的演示场景模板
```

演示前导出：

```text
hackathon-demo-backup-YYYYMMDD.json
```

如果当前场景被误改，可以使用“演示”按钮或导入 JSON 恢复。

## 6. 演示前一小时：浏览器准备

### 6.1 推荐浏览器布局

如果只有一台电脑，可以使用：

```text
Chrome 普通窗口：管理者
Chrome 无痕窗口：编辑者
Edge 普通窗口：编辑者
Safari 或另一台电脑：预览者
```

更推荐使用不同设备：

```text
主持人电脑：管理者
演示电脑 1：编辑者
演示电脑 2：编辑者
手机/平板：预览者
```

### 6.2 不要使用相同的普通标签页测试多个身份

当前用户名保存在浏览器本地存储中。如果在同一个浏览器的多个普通标签页中打开，可能出现：

- 多个标签显示同一个用户名；
- 角色选择相互覆盖；
- 本地场景缓存相互影响；
- 关闭一个标签导致 Awareness 状态变化不符合预期。

建议：

- 不同用户使用不同浏览器；
- 或使用无痕窗口；
- 或使用不同设备；
- 每个浏览器窗口都单独选择角色。

### 6.3 现场网络

提前确认：

- 所有设备能访问线上域名；
- Wi-Fi 不拦截 WebSocket；
- 手机热点可以作为备用网络；
- VPN、代理或企业网络不会拦截 `wss://`；
- 至少有一台设备可以使用备用网络。

如果现场网络不稳定，建议：

```text
主网络：活动现场 Wi-Fi
备用网络：主持人手机热点
```

## 7. 基础多人协作演示流程

以下流程不依赖鼠标光标功能，当前版本已经可以优先验证。

### 步骤 1：主持人打开线上地址

打开完整链接：

```text
https://<部署域名>/xiyou/?room=hackathon-demo
```

如果界面提供角色选择，选择：

```text
管理者
```

确认顶栏或协作状态条显示：

```text
已连接
```

### 步骤 2：确认主持人场景正确

检查：

- 演示场景名称正确；
- 场景对象已经加载；
- 左侧 Outliner 有对象；
- 中间 Viewport 有场景；
- 底部时间线和素材正常；
- 没有出现空白新场景覆盖已有场景。

### 步骤 3：其他参与者打开相同完整链接

每个人打开完全相同的：

```text
room
key
```

只有角色可以不同。

例如：

```text
https://<部署域名>/xiyou/?room=hackathon-demo&role=editor
```

### 步骤 4：确认在线人数

当其他人连接成功后，主持人应该看到：

```text
2 人在线
3 人在线
4 人在线
```

如果只有自己显示在线，先不要开始操作，优先排查 WebSocket 连接。

### 步骤 5：演示编辑者 A 移动对象

编辑者 A：

1. 在 Outliner 或 Viewport 选择悟空对象；
2. 使用移动工具；
3. 将对象向左移动；
4. 修改对象名称或位置。

主持人和其他编辑者应该看到：

- 对象位置变化；
- 选中状态变化；
- 对方在线头像或颜色变化；
- 如果支持软锁，显示“某某正在编辑此对象”。

### 步骤 6：演示编辑者 B 创建对象

编辑者 B：

1. 从内容浏览器拖出一个图片或光源；
2. 放入 Viewport；
3. 修改材质颜色；
4. 绑定到某个剧情节点。

其他用户应该实时看到新对象和属性变化。

### 步骤 7：演示不同对象同时编辑

为了避免两个用户同时修改同一个字段，现场可以这样分工：

```text
编辑者 A：修改悟空的位置
编辑者 B：修改结界符的颜色
预览者：移动鼠标并切换试玩模式
管理者：观察同步和发布检查
```

这样能展示多人协作，又不会因为同时编辑同一个字段产生视觉竞争。

### 步骤 8：演示撤销

让某一位编辑者执行：

```text
Ctrl + Z
```

说明：

```text
协作撤销优先撤销自己的操作，不是简单地回退整个团队的最新操作。
```

### 步骤 9：演示断开和重连

可以让一名参与者：

1. 暂时切换网络或关闭页面；
2. 其他人观察在线人数减少；
3. 重新打开同一个链接；
4. 观察重新进入房间；
5. 确认场景仍然可以同步。

如果现场时间紧，不建议主动做断网实验，避免引入不必要风险。

## 8. 增强演示：鼠标、用户名和角色颜色

## 8.1 目标效果

当协作者把鼠标移动到中间预览区时，其他人看到：

```text
      ↖
      A7K2M9
      编辑者
```

不同角色使用不同颜色：

```text
管理者：橙色
编辑者：蓝色
预览者：绿色
```

鼠标标签不能阻挡本地用户点击，因此必须使用：

```css
pointer-events: none;
```

## 8.2 随机用户名

没有账号体系时，每个浏览器首次进入生成一个随机名称。

建议字符集：

```js
const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'
```

去除容易混淆的字符：

```text
I、O、0、1
```

生成 6～8 位名称，例如：

```text
A7K2M9
Q8P4DX
N3W7F2K
```

建议保存到：

```js
localStorage.setItem('xiyou.guest.name', name)
```

读取逻辑：

```js
function getGuestName() {
  const storageKey = 'xiyou.guest.name'
  let name = localStorage.getItem(storageKey)

  if (!name) {
    const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'
    const bytes = crypto.getRandomValues(new Uint8Array(6))
    name = Array.from(bytes, byte => chars[byte % chars.length]).join('')
    localStorage.setItem(storageKey, name)
  }

  return name
}
```

显示时可以加前缀：

```text
访客 A7K2M9
```

或者只显示：

```text
A7K2M9
```

## 8.3 角色选择

首次进入房间时弹出：

```text
选择本次演示身份

[管理者] [编辑者] [预览者]
```

保存：

```js
localStorage.setItem('xiyou.guest.role', 'editor')
```

默认角色建议为：

```text
editor
```

如果不希望增加弹窗，也可以通过 URL 设置：

```text
?role=manager
?role=editor
?role=previewer
```

读取优先级建议：

```text
URL role
  → localStorage role
  → 默认 editor
```

## 8.4 Awareness 数据结构

鼠标位置、用户名、角色和颜色属于临时在线状态，不应该写入场景文档。

推荐使用 Yjs Awareness：

```js
{
  name: 'A7K2M9',
  role: 'editor',
  color: '#2563EB',
  cursor: {
    x: 0.42,
    y: 0.58,
    visible: true
  },
  sel: ['glb_wukong']
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `name` | 随机访客名 |
| `role` | `manager` / `editor` / `previewer` |
| `color` | 根据角色设置的颜色 |
| `cursor.x` | 鼠标在 Viewport 中的相对横坐标，范围 0～1 |
| `cursor.y` | 鼠标在 Viewport 中的相对纵坐标，范围 0～1 |
| `cursor.visible` | 是否在 Viewport 内 |
| `sel` | 当前选中的对象 ID |

## 8.5 为什么使用相对坐标

不要直接同步浏览器像素：

```js
{ x: 642, y: 318 }
```

不同设备的 Viewport 尺寸不同，像素位置会失真。

推荐同步：

```js
const rect = viewportElement.getBoundingClientRect()
const x = (event.clientX - rect.left) / rect.width
const y = (event.clientY - rect.top) / rect.height
```

渲染时再转换回来：

```js
cursor.style.left = `${peer.cursor.x * 100}%`
const top = `${peer.cursor.y * 100}%`
cursor.style.top = top
```

## 8.6 鼠标同步频率

不建议每一帧都发送 Awareness。

推荐：

```text
20～30 次/秒
```

可以使用简单节流：

```js
let lastSentAt = 0

function onPointerMove(event) {
  const now = performance.now()
  if (now - lastSentAt < 40) return
  lastSentAt = now

  publishCursor(event)
}
```

鼠标离开 Viewport 时发送：

```js
{ cursor: { visible: false } }
```

关闭页面前也可以清除本地 Awareness，但不能依赖 `beforeunload`，因为浏览器不保证它一定执行。WebSocket 断开后，Yjs Awareness 通常会让其他客户端移除该用户。


当前阶段颜色只用于识别角色，不代表真正权限。

## 9. 现场演示脚本

下面是一段可以直接照着讲的 3～5 分钟演示脚本。

### 0:00～0:30：介绍

> 这是一个在线的空间内容编辑器。它不是每个人各自打开一份本地工程，而是所有人进入同一个线上协作空间。

### 0:30～1:00：进入房间

主持人打开线上链接，其他几位参与者打开同一个链接。

> 现在可以看到，几个人已经进入同一个花果山空间。右上角的在线人数会增加，每个参与者都有自己的随机名称和颜色。

### 1:00～1:40：展示鼠标和角色

让不同参与者移动鼠标。

> 蓝色的是编辑者，橙色的是管理者，绿色的是预览者。鼠标位置和名称不是写入场景的，而是通过实时在线状态同步给其他人。

如果鼠标功能尚未完成，则改为：

> 现在先通过在线头像和选中状态区分不同参与者。鼠标位置同步功能会在下一版增强。

### 1:40～2:30：多人编辑

编辑者 A 移动悟空，编辑者 B 添加光源，主持人观察。

> 现在编辑者 A 在移动悟空，编辑者 B 同时给场景增加一个光源。两个人修改的是同一个空间文档，不需要互相传文件，也不需要合并 JSON。

### 2:30～3:00：选中状态和软锁

让两个人选择同一个对象。

> 当其他人正在编辑同一个对象时，系统会显示软锁提示。它不会粗暴阻止操作，但会提示团队成员避免相互覆盖。

### 3:00～3:40：试玩

预览者切换试玩模式或点击预览。

> 预览者可以在不直接修改场景的情况下查看当前效果。编辑者修改内容后，预览者可以马上看到更新结果。

### 3:40～4:20：撤销和发布检查

主持人执行撤销，打开发布检查。

> 协作撤销会优先撤销当前用户自己的操作。发布之前，系统还会检查资源引用、触发器、剧情节点和预算问题。

### 4:20～5:00：总结

> 这个模式的核心不是把工程文件发给每个人，而是把场景放在一个在线协作空间里。每个人通过浏览器进入，服务器负责实时同步，后续还可以加入账号、项目权限和发布版本管理。

## 11. 现场故障排查

## 11.1 页面能打开，但显示“未连接”

检查顺序：

```text
1. 浏览器 Console 是否有 WebSocket 错误
2. URL 是否包含 room
3. URL 是否包含正确 key
4. WebSocket 是否使用 wss://
5. 协作服务器是否运行
6. Cloudflare Tunnel / 反向代理是否运行
7. 当前网络是否拦截 WebSocket
```

常见原因：

- 邀请链接漏了 `key`；
- 当前页面连接了错误的 WebSocket 地址；
- 服务端令牌已经过期或被修改；
- 现场网络阻断 WebSocket；
- 协作容器停止；
- 反向代理没有转发 Upgrade。

## 11.2 页面能打开，在线人数不增加

通常说明：

```text
页面 HTTP 访问正常
但 WebSocket 没有成功连接
```

先让第二个用户刷新完整链接，再检查：

```text
wss://<部署域名>/xiyou-yjs
```

是否能在浏览器 Network 面板看到 WebSocket 连接。

## 11.3 在线人数增加，但场景不一致

检查：

- 两个人的 `room` 是否完全相同；
- 是否有人打开了 `?reset=1`；
- 是否有旧的 `localStorage` 场景覆盖云端场景；
- 是否某个浏览器连接超时后仍停留在本地模式；
- 是否打开了不同线上部署版本的前端；
- 服务端是否有房间持久化或初始化逻辑问题。

现场恢复方式：

```text
1. 暂停所有编辑
2. 主持人导入备份 scene.json
3. 确认所有用户重新同步
4. 再继续演示
```

## 11.4 鼠标光标不显示

检查：

- 鼠标是否移动到了中间 `#viewport-wrap`；
- `pointermove` 是否绑定在正确元素；
- Awareness 是否包含 `cursor`；
- `collab-peers` 事件是否包含远端用户；
- `cursor.visible` 是否为 `true`；
- Overlay 是否被 CSS 隐藏；
- `.collab-cursors` 是否覆盖在 Viewport 上方；
- 是否错误设置了 `display: none`；
- 是否因为 `pointer-events` 或 z-index 不正确导致显示异常。

## 11.5 鼠标能显示，但挡住了点击

确认：

```css
.collab-cursors,
.collab-cursor {
  pointer-events: none;
}
```

协作者鼠标只能用于显示，不能拦截本地交互。

## 11.6 所有人显示同一个随机名字

原因通常是：

- 使用了同一个浏览器普通窗口；
- 多个标签页共享同一个 `localStorage`；
- 随机名称生成逻辑只生成了一次并写入了共享存储；
- 测试时复制了固定 name 参数。

处理：

- 使用无痕窗口；
- 清除该浏览器的 `xiyou.guest.name`；
- 使用不同设备或不同浏览器；
- 重新打开链接。

## 11.7 编辑者误改场景

恢复方式：

1. 先暂停所有人操作；
2. 主持人使用撤销；
3. 如果无法恢复，导入备份 JSON；
4. 所有人刷新并重新连接；
5. 继续使用预先准备的演示步骤。

不要在现场直接重启生产数据库或删除整个房间。

## 11.8 服务器重启后场景丢失

这说明当前协作服务可能只在内存中保存 Yjs 文档，或者持久化未正确配置。

现场应对：

```text
1. 不要主动重启协作容器
2. 使用主持人本地 scene.json 恢复
3. 重新导入到 hackathon-demo
4. 检查服务端持久化配置
```

后续必须增加 Yjs 持久化和场景快照，不能把现场演示依赖在内存房间上。

## 15. 重要边界：演示角色不等于正式权限

黑客松阶段可以通过 URL 或本地存储选择角色：

```text
?role=manager
?role=editor
?role=previewer
```

但这种方式不安全，因为用户可以自己改 URL：

```text
?role=manager
```

因此当前角色只能用于：

- 鼠标颜色；
- 用户名旁边的标签；
- 在线成员识别；
- 演示现场分工；
- UI 状态展示。

不能依赖它实现真正权限。

正式权限应升级为：

```text
账号
  → 工作空间成员关系
  → 项目成员角色
  → 服务端权限判断
  → 短期协作 Ticket
  → WebSocket 服务端鉴权
```

尤其是预览者角色，不能只通过前端隐藏按钮来阻止修改。正式版本应让预览者读取场景快照或使用服务端只读协作通道。

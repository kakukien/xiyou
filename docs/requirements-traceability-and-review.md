## 2. P0 设计审查结论

### P0-1：不能让模型直接改场景

**结论：通过。** AI 只返回 schema 受限的 ops；客户端和服务端都校验；底座、权限和素材库不在 AI 操作权限内。

### P0-2：没有明确位置时不能自动放置

**结论：通过。** 使用 Viewport 点击、选中对象、锚点/区域和相机射线上下文；没有可信位置时追问或待确认。

### P0-3：模型失败不能造成半截场景

**结论：通过。** 计划阶段先校验；执行使用 batch 和 operationGroupId；失败提供整组撤销。

### P0-4：游客不能读 Draft

**结论：通过。** Runtime 首选 Release URL/API；本机 localStorage 仅本地编辑器回退；旧 Session 不强制切换。

### P0-5：AI 不能伪造不存在的资产

**结论：通过。** 资源只能使用目录中的 assetId；不明确时展示候选或明确使用占位。

### P0-6：语音不能绕过确认

**结论：通过。** 最终识别文本可编辑；低置信度和高风险操作必须确认。

### P0-7：实时更新不能混淆 Draft/Release/Session

**结论：通过。** 三种实时语义已经拆分，第一阶段只交付 Draft 协作与 Release 通知。

### P0-8：刷新不能静默清空数据

**结论：已完成本地草稿层。** 已移除按“花果山觉醒”清空的逻辑，增加 `draftId/updatedAt`、备份恢复和回归测试；跨设备永久存储仍属于后续 Release API 工作。

### P0-9：Runtime 必须进入构建产物

**结论：已完成。** Vite 多页面入口已加入 `runtime.html`，`npm run build` 与回归测试均验证 `dist/runtime.html` 存在。

### P0-10：发布资产必须可持久化

**结论：部分通过。** 发布检查仍会阻止临时 URL；本轮新增 Release payload 与 JSON 下载入口，但真实对象存储/Release API 仍待接入。

## 3. 主要风险与取舍

| 风险 | 影响 | 决策 |
|---|---|---|
| 任意第三方 API 格式不同 | 高 | 只接 Provider Adapter，不在浏览器直连 |
| 模型幻觉资产/坐标 | 高 | 资源 ID 与位置置信度校验；不确定就追问 |
| 本地 STT 包体和性能 | 中 | 先用浏览器/服务端 Provider，本地模型作为可选部署 |
| 手机定位漂移 | 高 | QR/图锚/VPS 优先，GPS 仅粗定位，显示置信状态 |
| Yjs 远端覆盖本地 | 高 | 初始同步前做摘要比较和用户选择，自动备份 |
| Release 与 Draft 混用 | 高 | Runtime 只读 Release，发布入口生成版本化 URL |
| 低端设备渲染压力 | 中 | 对象数、材质、粒子和纹理预算进入发布检查 |
| 用户语音隐私 | 高 | 明示发送范围、默认不永久保存音频、可选本地识别 |
| AI 费用不可控 | 中 | token/请求/并发/用户配额和超时 |

## 4. 开发准入门槛

在进入代码开发前，必须满足：

- [x] 需求拆分为 Editor、Capture、Runtime 三个板块；
- [x] Draft/Release/Runtime/Session 数据边界已定义；
- [x] AI 权限、操作协议、确认和撤销已定义；
- [x] 语音、第三方模型和定位降级策略已定义；
- [x] 已定位现有“信息消失”的代码路径；
- [x] 已列出 P0 阻塞项；
- [ ] 用户/项目级 Provider 配置界面与服务端 API 合约完成；
- [ ] 持久化 Release API 或明确的后端接口负责人和部署位置；
- [ ] 真实模型 API Key、STT Key 和生产域名可用；
- [ ] 目标移动设备与浏览器矩阵确定。

最后四项不阻塞本地架构和 mock 开发，但阻塞“生产级第三方接入”和“跨设备发布上线”声明。

## 5. 开发完成后的强制验证

### 静态与单元

- `npm run build`
- `npm run test:smoke`
- AI plan schema、ops 白名单、引用解析、批量撤销
- migration、localStorage 备份、协作初始同步决策
- Provider timeout/非法响应/限流

### 浏览器

- 首次打开空场景
- 已有对象刷新恢复
- `?room=demo` 与其他 room 隔离
- 旧演示数据不被清空
- AI 文本添加、相对定位、触发器、撤销
- 语音权限允许/拒绝/无识别
- 试玩模式禁止修改
- 生产产物访问 `index/show/runtime`

### 双端/现场

- 电脑发布 v1，手机扫码读取 v1
- 电脑发布 v2，旧手机提示更新，新手机读取 v2
- QR/图锚/VPS/GPS/手动参考点降级
- 箱子 tap/enter/gaze/hold 与 Session 重置
- 远端资源失败和相机拒绝仍可恢复

## 6. 审查后的开发顺序

1. P0-8/P0-9 本地基线已完成；继续补 P0-10 的 Release API/对象存储。
2. AI 计划/确认/事务/撤销已落地，继续补服务端 Provider Adapter。
3. 继续补服务端 STT、第三方模型鉴权和语音候选确认。
4. 补 Release API/二维码/跨设备 Runtime 验收。
5. 最后扩展风格化、共享游客状态、真实空间物理交互等 P1/P2 能力。

## 7. 审查结论

本轮本地基线和 AI/元素基础链路已进入开发，但不能宣称生产级跨设备发布和任意第三方模型接入已完成。当前最优先的工程动作是：

```text
数据不会被启动代码清空
→ 本地/远端不会静默互相覆盖
→ 发布页面确实进入构建产物
→ 临时资源不会伪装成正式发布资源
```

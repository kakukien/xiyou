# 造梦 · 故事空间

面向展陈、景区和现场创作团队的 Web 空间编辑器。它把真实空间或高斯泼溅底座变成可继续创作的场景：导入空间素材 → 校准坐标与碰撞 → 布置模块元素 → 编排互动与剧情 → 试玩、发布。

## 能力概览

- **场景编辑**：三栏工作区、场景对象树、3D 视口、变换工具、吸附、地面锁定、区域限制和对象属性。
- **空间生成**：支持视频、序列帧及 PLY / SOG / SPZ 等高斯资产；生成任务可排队、恢复，刷新页面后在“任务记录”中继续查看进度。
- **互动编排**：通过触发条件、动作、时间线、剧情节点和定位锚点制作可试玩的空间故事。
- **模块元素**：桌子、椅子、环境、游戏道具、特效和交互装置都带有稳定的分类、标签与语音别名，可拖入场景，也可由 AI 按标签查找并添加。
- **多人协作**：工程草稿按协作房间隔离，支持场景实体同步、在线状态、选择提示和个人撤销 / 重做。
- **游客运行端**：发布快照可由 Runtime 加载，支持相机、方向、定位、二维码 / 条码及 tap、gaze、hold、enter 等互动触发。

## AI 场景助手

右下角 **AI** 面板用于用自然语言提出场景修改。每次修改都会先展示计划，确认后才执行，并支持撤销本次修改。

可执行的典型指令：

- “在视口落点放一把椅子。”
- “在选中的桌子右侧两米处放一个模块元素。”
- “给这个对象添加点击反馈和一段入场动画。”

AI 只编辑场景内容，不直接修改底座、素材库或编辑器配置。已有模块元素会依据 `element_id`、语音别名和标签解析；未导入或未登记的角色模型，需要先通过“导入素材”加入素材库，才能被布置到场景中。

## 本地运行

```bash
cd editor
npm install
npm run dev       # http://127.0.0.1:5199
npm run build     # 生成 dist/
```

若要使用视频生成高斯空间，开发服务器会自动尝试启动本地 GPU Worker；也可以单独启动：

```bash
node tools/gpu-worker.mjs serve --port 8787
```

Worker 提供本地任务队列、进度查询、取消 / 恢复和输出资产读取。真实重建需要本机可用的 FFmpeg、COLMAP、Brush 或兼容重建器；未配置时只会生成重建输入包和质量报告，不会伪装成已完成的 Gaussian 训练。

## 数据与安全边界

- 草稿、任务索引和界面偏好默认保存在浏览器本机；任务本体由 Worker 管理，页面关闭后仍可通过任务 ID 查询。
- 机密配置只从本机环境变量、部署平台 Secret 或运行时注入读取，不写入 README、源码示例、截图和提交记录。
- 协作凭证、发布凭证、模型服务凭证和本地引擎路径均不属于项目文档内容；分享链接前请先移除查询参数中的凭证。
- 本仓库只保留通用开发说明。部署地址、房间名、令牌、代理地址和服务器路径请在部署环境或团队密码管理器中维护。

## 目录

- `editor/`：Vite + Three.js 编辑器、Runtime 和场景工作台。
- `editor/src/core/`：场景数据、协作、模块元素、AI 操作协议、重建 Provider。
- `editor/src/ui/`：顶栏、大纲、属性、资源库、任务记录和 AI 面板。
- `tools/gpu-worker.mjs`：本地媒体分析、上传任务、重建前处理与任务查询服务。
- `docs/`：设计系统、需求追踪、功能方案和验收记录。
